# Что изменено во второй версии (после замечаний преподавателя)

## 1. Рабочая инструкция запуска
- README полностью переписан.
- Добавлены точные команды для Windows (PowerShell) и Mac/Linux.
- Явно указано, что без `.env` и ключа сервис не заработает, и какой формат ошибки вернётся.

## 2. Единый формат ошибок
- Если `ROUTERAI_API_KEY` не задан, сервис сразу возвращает стандартизированный ответ:
  ```json
  {
    "success": false,
    "request_id": "...",
    "error": {
      "code": "ROUTERAI_AUTH_ERROR",
      "message": "ROUTERAI_API_KEY is not set..."
    }
  }
  ```
- Больше нет «сырых» падений при отсутствии ключа.

## 3. Честный test runner
- Сравнение только по полям, которые реально указаны в `expected`.
- Явная проверка `null` для бюджетов (важно для англоязычных заявок с $).
- Отдельная метрика по `needs_human_review`.
- Добавлена проверка повторяемости (3 запуска) для TC-001, TC-002, TC-010.
- Всегда пишется `reports/latest_report.json` + timestamped отчёт.

## 4. Системный промпт
- Добавлено правило: если сумма указана не в рублях ($/USD/EUR) → `budget_min_rub` и `budget_max_rub` = null (не придумывать и не пересчитывать).
- Усилено правило про противоречия → обязательно `needs_human_review: true`.
- Уточнены правила `lead_quality` строго по разделу 9 ТЗ.

## 5. Тестовые кейсы
- Для английских заявок с бюджетом в долларах ожидаемые `budget_*` изменены на `null`.
- Кейсы с противоречиями проверяют в первую очередь `needs_human_review: true`.

## 6. Материалы для сдачи (п. 15 ТЗ)
- Добавлен `docs/example_success_response.json`.
- Добавлен этот файл `CHANGES.md`.
- Runner пишет отчёт в репозиторий (`reports/latest_report.json`).
